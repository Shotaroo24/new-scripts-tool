## 0. 背景と方針

- Filmora はパイプラインから完全撤去する。
- BGM・音量調整・粗カットは CapCut で先行完結し、**音声込みのマスター動画1本**（以下「マスター」）として持ち込む。
- srtgen で行うのは次の3つのみ: **字幕タイミング調整（既存）／カットの微調整／字幕焼き込み書き出し**。
- srtgen は引き続きブラウザ完結（サーバ・アップロードなし）。外部依存は書き出し用に **mediabunny を1ファイル vendor する**のみ（ビルドステップなしを維持）。
- テロップ装飾は**現行実装のスタイル定数をそのまま使う**。新規デザインは追加しない（§5.3）。

### 0.1 非スコープ（明示的にやらないこと）

複数素材の組み立て、トランジション、音量・BGM 調整、テロップ装飾の追加・アニメーション、クリップ音声の個別制御、モバイル対応、Redo。

## 1. 用語と全体像

| 用語 | 意味 |
|---|---|
| マスター | CapCut 書き出しの動画ファイル1本。音声込み。ソース時間軸を持つ |
| 出力タイムライン | 完成動画の時間軸。動画区間の連結で構成される |
| 動画区間 (segment) | マスターの一部分。`{srcInMs, durMs}` |
| 総尺 T | 出力タイムラインの長さ。`Σ segments.durMs` で常に導出 |

ワークフローの順序は従来通り「**原稿 → 字幕タイミング確定 → マスター読み込み → カット微調整 → 書き出し**」。ただしマスター読み込み後も字幕の尺編集は禁止しない（§3.4 の連動リップルにより音ズレが構造的に起きないため、ロック機構は設けない）。

## 2. データモデル

既存の原則を全面的に踏襲する: **全時間は ms 整数**、開始時刻は保持せず**常に累積導出**、ギャップ 0 が構造的不変条件。

```js
// 既存（変更なし）
subs = [{ text, durMs, edited, delim, en }]

// 新規
master = { fileName, durationMs, width, height }   // 読み込み時にメタデータから取得
segments = [{ srcInMs, durMs }]                    // 出力順の配列。出力位置は累積導出
```

### 2.1 不変条件

1. `segments` は常に1個以上。マスター読み込み直後は `[{srcInMs: 0, durMs: master.durationMs}]`。
2. 各区間は `0 <= srcInMs` かつ `srcInMs + durMs <= master.durationMs`（ソース範囲内）。
3. 総尺 T = `Σ segments.durMs`。別変数として保持しない（導出のみ）。
4. 区間の最小尺は `MIN_DUR_MS`（=300ms、既存定数を流用）。
5. 出力時刻 → ソース時刻の写像 `outputToSrc(tMs)` は区間の累積で一意に決まる（§4.1）。

### 2.2 セッション保存

既存の localStorage セッション（`srtgen:session:v1`）に `segments` と `master.fileName / durationMs` を追加し、`SCHEMA_VERSION` を 3 に上げる（旧データは既存方針通り破棄）。動画ファイル本体は保存できないため、復元時はファイル名を表示して再選択を促し、**選択ファイルの尺が保存値と一致しない場合は警告して segments を初期化**する。

## 3. 動画トラックの編集操作

タイムラインは既存の字幕トラックの下に動画トラックを1段追加した2トラック構成。

### 3.1 トラックフォーカス

クリックしたトラックがフォーカスを持つ（視覚的にハイライト）。`S` / `Delete` はフォーカス中のトラックに作用する。`↑↓` は**フォーカス中のトラック内でのクリップ/区間移動**に作用する（字幕フォーカス時: 字幕クリップの前後移動。動画フォーカス時: 動画区間の前後移動。2026-07-25改訂: 当初「トラック共通」としていたが、動画区間の選択移動を字幕側と同等の操作感にするためフォーカス依存に変更）。`Space` 再生・`←→`（0.1秒ステップ移動）・`Ctrl+Z`・`L`（再生速度切替、§4.4）はトラック共通。マスター未読み込み時は字幕トラック固定（現行と同一挙動）。

### 3.2 操作一覧（動画トラックフォーカス時）

| 操作 | 挙動 |
|---|---|
| `S` | **再生ヘッド位置**で区間を分割。分割直後は `srcIn` が連続する2区間になるため**映像は無変化**（切れ目だけが入る） |
| `Delete` | **選択中の区間**をリップル削除。映像と音声がその分消え、総尺が縮む。字幕は §3.4 の規則で連動 |
| `↑` / `↓` | 選択を隣（前/次）の区間へ移動し、その区間の頭へシークする（§3.1） |
| `←→` | 再生ヘッドを0.1秒ステップ移動（トラック共通。フォーカス中のトラックを問わず動作する） |
| 区間右端ドラッグ | out 点トリム（`durMs` 変更）。後続区間は前に詰まる（リップル）。字幕連動あり |
| 区間左端ドラッグ | in 点トリム（`srcInMs` と `durMs` を同時に変更）。字幕連動あり |
| 区間本体ドラッグ | **区間の並べ替え**（§3.6）。微小な移動はクリックとして扱う |
| 区間クリック | 選択 + 区間頭に頭出し |

尺の刻みは 0.1 秒（内部は ms 整数）、最小 300ms。既存の字幕トラック操作（S トリム / M 結合 / 右端ドラッグ）は一切変更しない。ただし字幕トラックの `Delete` は動画トラックとの一貫性のため**選択中のクリップ**を対象とするよう改訂した（2026-07-25、§3.6）。

### 3.3 スナップ

区間境界のドラッグと `S` のカット位置は次の3つに吸着する: **字幕境界／再生ヘッド／0.1 秒グリッド**。吸着範囲は画面上 6px 相当（ズーム依存）。`Alt` 押下中はスナップ無効。これにより「`↑` で字幕頭にジャンプ → `S` でカット」の2キーで字幕境界とカット位置が正確に一致する。

### 3.4 字幕の連動リップル（本仕様の核）

マスターには音声が含まれるため、動画の削除・トリムは音声の削除でもある。字幕は音声（喋り）に合わせて打たれている前提なので、**動画トラックの編集で出力範囲 `[a, b)` が消えるとき、字幕トラックも同じ範囲だけ詰める**。規則:

1. 削除範囲より後ろに完全に位置する字幕: そのまま（累積導出により自動的に `b - a` だけ前へずれる）。
2. 削除範囲と重なる字幕: 重なった長さを `durMs` から減算する。このとき `edited: true` にする（cps 再計算から保護）。減算結果は MIN_DUR_MS を下回ってもよい（音との同期を優先。1ms 未満になる場合のみ 3. を適用）。
3. 字幕が削除範囲に完全に含まれる場合: 字幕ごと削除する。
4. 本処理と動画側の変更は **Undo 1エントリ**として一体で記録する（両トラックのスナップショット）。

この規則により、ジャンプカット（喋りの間・失敗テイクの削除）を行っても映像・音声・字幕のズレは構造的に発生しない。

### 3.5 Undo

既存の Undo スタック（50件・Redo なし）に統合する。1操作 = 1履歴。動画トラックを含む操作（分割・削除・両端トリム・並べ替え）は `subs` と `segments` の両方をスナップショットする。

### 3.6 選択の独立化・区間の並べ替え（2026-07-25追記）

**選択の独立化**: 字幕クリップの選択と動画区間の選択は、それぞれ独立した状態として管理する。一方を選択（クリック・矢印キー移動）しても、もう一方の選択状態は変化しない。両トラックとも「選択中のクリップ/区間」へシークする点は従来通りだが、シークによって共有の再生ヘッド（`headTimeMs`）が動いても、**選択していない側のトラックのハイライトは再計算されない**（以前は両トラックとも「再生ヘッド位置にあるもの」を自動的にハイライトしていたため、一方の操作で他方の選択が意図せず変わっていた）。

再生ヘッドが指す位置は §4.1 のプレビュー（「今どこを再生/表示しているか」）にのみ使う。`S`（分割・トリム）は引き続き再生ヘッド位置に作用し、`Delete` は選択中のクリップ/区間に作用する（§3.2）。

**区間の並べ替え**: 動画区間本体をドラッグすると、`segments` 配列内の順序を入れ替えられる（`srcInMs` / `durMs` は変更しない）。出力位置は既存どおり累積導出のみで決まるため、並べ替え後もギャップ0の不変条件は自動的に保たれる。字幕トラックへのリップル連動は行わない（§3.4 の連動リップルは「出力範囲が消える」編集が対象であり、並べ替えは何も消えないため対象外）。Undo は §3.5 の通り一体で記録する。

## 4. プレビュー

### 4.1 合成再生

- マスターは `URL.createObjectURL` で `<video>` 要素1個に読み込む（DOM 上は非表示でよい。描画は §4.2）。
- 出力時刻 → ソース時刻の写像:
  `outputToSrc(tMs)`: 区間の累積開始時刻 `outStart[i]` を求め、`tMs` が属する区間 `i` に対して `segments[i].srcInMs + (tMs - outStart[i])` を返す。境界判定は既存 `clipAt` と同じく整数比較のみ。
- 再生は `<video>` をそのまま再生し、区間境界に達したら次区間の `srcInMs` へ `currentTime` シーク。シーク遅延（数十ms〜）は v1 では許容する（プレビュー品質の問題であり、書き出しには影響しない）。
- **音声はマスターの音声をそのまま使う**（同一ファイルなので映像と自動同期。ミュート制御・別音声トラックは存在しない）。
- 頭出し（ルーラークリック・`↑↓` ジャンプ・区間クリック）は `outputToSrc` で写像してシークする。

### 4.2 描画

プレビュー枠は既存の 9:16 実寸プレビューを流用し、背景を「現在フレームの映像」に差し替える。実装は Canvas 合成（`drawImage(video)` → 字幕描画）を基本とする。**字幕の描画パラメータは既存関数（`previewFontSizePx` / `previewStrokeWidthPx` / `previewBaselineOffsetPx` / `previewSafeMargins`）をそのまま使い、書き出し（§5.2）と同一の描画関数を共有する**。行数判定バッジ・安全幅表示等の既存 UI は維持する。

### 4.3 読み込み時チェック

マスター選択時に次を検証し、問題があれば読み込み前に警告する:

- `<video>` で再生可能か（`canplay` 到達）。
- WebCodecs でデコード可能か。mediabunny の `Input` でファイルを読み込み、`InputVideoTrack.canDecode()` / `InputAudioTrack.canDecode()` で実ファイルのトラック・コーデックに基づいて判定する（実装レビューにより、当初案の `VideoDecoder.isConfigSupported` へのコーデック文字列推測から、mediabunny のデマルチプレクサを使った実ファイルベースの判定に変更。2026-07-25、Phase 2 実装時）。
- 音声トラックの有無（無い場合は「音声なしで書き出されます」と警告のみ、続行可）。

### 4.4 再生終了時・再生速度（2026-07-25追記）

- **再生終了後の表示**: 再生ヘッドが総尺 T に到達して自動停止した直後は、プレビューを黒画面にする（最終フレームを静止画として残さない）。マスター未読み込み時は字幕プレビューも非表示にする。ユーザーが再度シーク・再生した時点で通常表示に戻る。
- **再生速度**: `L` キーで再生速度を `1x → 2x → 3x → 1x` の順にサイクルする（トラック共通）。現在の速度を再生ボタン付近に表示する。速度は `<video>` の `playbackRate` にも反映し、字幕タイムラインの進行速度（`headTimeMs` の進み方）と同期させる。書き出し（§5）には一切影響しない（書き出しは常に等速でレンダリングする）。

## 5. 書き出し

### 5.1 出力仕様

| 項目 | 値 |
|---|---|
| コンテナ | MP4 |
| 解像度 | 1080 × 1920 固定（マスターが異なる場合は cover fit: 短辺合わせ + 中央クロップ） |
| 映像コーデック | H.264（WebCodecs ハードウェアエンコード、mediabunny 経由）。ビットレートは明示的に **10Mbps** を指定する（2026-07-25改訂: 当初 mediabunny の `QUALITY_HIGH` 定数を使用していたが、1080×1920 では約6Mbpsにしか解決されず動きの多い素材で画質不足になることが判明したため） |
| fps | 30 固定 |
| 音声 | AAC 128kbps。マスター音声を区間ごとに切り出して連結し再エンコード（カットがあるためパススルー不可。v1 では常に再エンコードで統一） |
| ファイル名 | `video_YYYYMMDD_HHMM.mp4` |

### 5.2 レンダリング規則

1. フレーム境界は**累積 ms から導出**する: フレーム `n` の出力時刻は `n * 1000 / 30` ms（実数）、これを `outputToSrc` で写像してソースフレームを取得する。区間ごとの個別丸めは禁止（既存の累積丸め方式と同思想。隙間・重複フレームを構造的に排除）。
2. 各フレームは 1080×1920 の Canvas に `drawImage`（cover fit）→ **プレビューと同一の字幕描画関数**で字幕を上書き → mediabunny の CanvasSource / VideoEncoder に渡す。
   - **フレーム取得は区間ごとの範囲イテレータ（`CanvasSink.canvases(startSec, endSec)`）で順次デコードする**（2026-07-25改訂）。当初は出力フレームごとに独立して `CanvasSink.getCanvas(timestamp)` を呼んでいたが、これは mediabunny のドキュメントが明記する非推奨パターン（同一パケットの再デコードを繰り返す）であり、書き出し品質低下（低ビットレートと合わせてカクつき・低品質の原因）につながっていた。区間内は出力時刻・ソース時刻とも単調増加するため、区間の先頭から1回だけ順次デコードし、各出力フレームには「そのフレームのソース時刻以下で最新のデコード済みフレーム」をマージウォーク方式で割り当てる（`CanvasSink.getCanvas` と同じ「floor選択」のセマンティクスを維持）。ソース fps が出力(30fps)を下回る場合に生じるフレーム重複は正常な挙動（アップサンプリング）であり、書き出し時に診断ログ（`console.info`）で件数を確認できる。
3. 字幕の表示判定は既存 `clipAt(subs, tMs)`（整数 ms 比較）を使う。
4. 進捗バー（フレーム数ベース）とキャンセルボタンを表示する。書き出し中は編集操作をロックする。

### 5.3 テロップ描画スタイル（確定・現行定数を流用）

1080×1920 空間で以下。**新規の値は一切導入しない**:

- フォント: `bold {fontSize × calibration}px "Times New Roman"`（`FONT_SIZE_DEFAULT = 55`、calibration は既存 UI の値）
- 縁取り: `STROKE_WIDTH_AT_1080 = 6`、黒、`paint-order: stroke fill` 相当（Canvas では strokeText → fillText の順）
- 文字色: 白
- 位置: 中央揃え、ベースライン = 映像下端から `SUBTITLE_BASELINE_FROM_BOTTOM = 390`
- 折り返し: なし（改行は字幕テキスト内で確定済み。2行時の行送りはプレビューの実装値と一致させる）
- 安全幅 900px（`SAFE_WIDTH_1080`）の判定・キャリブレーションは既存のまま

**受け入れ基準: 同一フレームのプレビュー表示と書き出し結果のスクリーンショット比較で、字幕の位置・サイズ・縁取りが一致すること**（描画関数を共有するため、ズレが出た場合は実装バグ）。

### 5.4 timeline.json（セーブ/ロード形式）

外部レンダラー受け渡し用ではなく**作業状態の保存・復元**が主目的（将来レンダラーを外出しする場合の分離点も兼ねる）。

```json
{
  "version": 1,
  "master": { "fileName": "master_capcut.mp4", "durationMs": 67000 },
  "segments": [ { "srcInMs": 0, "durMs": 16000 }, ... ],
  "subs": [ { "text": "...", "durMs": 1270, "edited": true, "delim": "", "en": "..." }, ... ],
  "cps": 12,
  "style": { "fontSize": 55, "calibration": 1.0 }
}
```

- 保存: ダウンロード（`timeline_YYYYMMDD_HHMM.json`）。
- 読み込み: JSON 選択 → 内容復元 → マスターのファイル再選択を促す（§2.2 の尺チェック）。
- `version` 不一致・スキーマ不正は読み込み拒否（原稿テキストと同じく黙って改変・補正しない）。

### 5.5 SRT / 原稿モード

既存の SRT ダウンロード・原稿モードは無変更で維持する。SRT は字幕トラックのみから生成する（動画トラックの状態に依存しない）。

### 6.2 モジュール方式

ES Modules（`<script type="module">`）を採用する。影響: **`file://` のダブルクリック起動は非対応になる**（Vercel URL またはローカルサーバ前提。README のこの記述を更新する）。代わりに tests から `src/core/*` を Node で直接 import でき、現行の「index.html からロジックを抽出して実行する」方式より二重管理リスクが下がる。core 層は DOM・`window` を参照しないことを規約とする（measureFn 注入方式は既存踏襲）。

## 7. 受け入れテスト（新規分の核心項目）

1. **保存則**: 任意の分割・削除・トリム列の後も `Σ durMs` と各区間のソース範囲(§2.1-2)が整合し、全値が ms 整数であること。
2. **分割の無害性**: `S` 直後の segments が写像 `outputToSrc` として分割前と完全一致すること。
3. **字幕連動リップル**: §3.4 の 4 規則（後方シフト／部分重なり減算+edited化／完全包含削除／Undo一体復元）。境界一致（`a` または `b` が字幕境界と一致）のケースを含む。
4. **outputToSrc**: 区間境界の前後 1ms・総尺ちょうど・総尺超えの各点で整数比較のみで正しい値/クランプを返すこと。
5. **フレーム導出**: 30fps・複数区間で、隣接フレームのソース参照に隙間・重複が生じないこと（累積導出の検証）。
6. **timeline.json ラウンドトリップ**: 保存→読み込みで `segments` / `subs` / `cps` / `style` が完全一致。version 不一致は拒否。
7. **描画一致**: プレビューと書き出しの字幕描画が同一関数を経由していること（ユニットではなく実装レビュー + スクリーンショット比較で確認）。
