# srtgen タイムライン編集モード 実装仕様書

対象リポジトリ: `Shotaroo24/new-scripts-tool`（main）
対象ファイル: `index.html` / `styles.css` / `src/core/*.js` / `src/ui/*.js` / `src/app.js`（ローカルファイル間の分割のみ可。CDN・外部ライブラリ・ビルドステップは導入しない。外部依存ゼロ・全処理クライアント完結は絶対条件）
既存仕様書: `srtgen-web-spec.md` — 本書と矛盾する場合は本書が優先。ただし「SRT出力の時刻計算」「SRT形式」「区切り文字による分割ルール」は既存仕様をそのまま踏襲する。

---

## 1. 目的

現在のsrtgenは「原稿貼り付け → 12cps自動計算 → SRT出力」の一方通行に加え、字幕クリップの尺・分割・結合を調整するタイムライン編集モードを持つ。本書はタイムライン編集モードの全仕様（データモデル・UI・永続化・英訳併記・9:16実寸プレビュー・行数判定）を定義する。動画トラックの読み込み・編集やMP4書き出しは扱わない（CapCut等の動画編集ソフト側の役割。11節参照）。

作業フロー全体:

```
原稿貼り付け（既存） → [タイムラインで調整] → タイムライン編集モード → [SRTダウンロード]
                          ↑                    |
                          └── [原稿に戻る]（書き戻し・確認ダイアログなし）
```

原稿が編集されずに往復する限り、タイムラインの手動調整（尺・テキスト・英訳・ズーム・ヘッド位置・calibration・フォントサイズ）は失われない。

## 2. データモデル

- 字幕は配列 `subs = [{ text: string, durMs: number, edited: boolean, delim: string, en: string }, ...]` で保持する。
- **`durMs` は整数ミリ秒。** 内部の時間計算（累積開始時刻・クリップ境界判定・SRT変換）はすべてこの整数msのみで行い、途中で浮動小数を経由しない。
  - 生成時・cps再計算時: `Math.round((文字数 / cps) * 1000)` で整数ms化。**文字数はアラビア語本文のみで数える。英訳・改行は尺に一切影響しない。**
  - ドラッグによる直接指定: px→msの変換値を`Math.round`で1ms単位に丸めるのみ。**人為的なスナップ（0.1秒刻み等）は入れない。**
  - 最小尺は **300ms**。いかなる操作でもこれを下回れない。
- `edited`: ユーザーが尺・テキストを明示的に変更したクリップは `true`。cpsスライダーによる自動再計算は `edited:false` のクリップにのみ適用される。
- `delim`: 原稿パース時にこのクリップの直後で**除去された**区切り文字（`.` `،` `,` のみ）。「残す」系の文字（`؟` `?` `!` `—`）は本文側に既に存在するため `delim` は空文字にする（二重出力防止）。区切り文字が連続する場合、削除系のみを連結して記録する（例: `...` → `delim="..."`）。末尾クリップ（区切りなしで終わる）は `delim=""`。
- `en`: このクリップに対応する英訳（1クリップ = 1行）。既定は空文字。**SRT出力には一切含めない。**
- 各字幕の開始時刻は**保存しない**。常に先頭からの `durMs` の累積で導出する（整数の加算のみのため誤差蓄積ゼロ）。
- **不変条件: 字幕間ギャップは常に0。** 尺を変更すると後続の開始時刻は自動的にズレる（リップル）。ギャップや重なりが生じる状態は表現不可能であること。

### SRT出力

`durMs` は既に整数msのため、先頭から単純に加算するだけで累積誤差は原理的に発生しない。形式は既存どおり標準SRT（`HH:MM:SS,mmm`）、UTF-8、BOMチェックボックス連動。**cue本文は `text` のみを使用し、`en` は一切出力しない。**

### 原稿改変禁止ルールとの整合

既存の「原稿テキスト一切改変禁止」は**自動変換の禁止**である。以下は許可される明示的なユーザー操作であり、この禁止事項の対象外とする:
- 本モードで追加する「ユーザーによる明示的なテキスト編集」（タシュキール除去・数字統一・RLM挿入・Unicode正規化などの自動処理は行わない。入力された文字列をそのまま保持・出力する）
- 「原稿に戻る」時の書き戻し（3.3節参照）。クリップ列から原稿テキスト・英訳テキストを再構成する処理そのものは、ユーザーが編集モードで行った操作の結果を反映する目的の変換であり、原稿の自動改変ではない。

## 3. モード遷移

### 3.1 基本フロー
1. **入力モード**（既存画面）: 原稿テキストエリア、英訳テキストエリア、cps数値入力、BOMチェックボックス、「タイムラインで調整」ボタン。
2. 「タイムラインで調整」押下 → 3.2節の判定に従い、生成または復元して**編集モード**へ。
3. 編集モードの「原稿に戻る」ボタン → **確認ダイアログなし**で即座に、3.3節の書き戻しを行い入力モードへ戻る。`subs` と履歴・ズーム段・ヘッド位置・calibration・フォントサイズはメモリ上に保持され続ける（破棄しない）。
4. SRTダウンロードは編集モードから実行（`subs` ベース、`en` は含まない）。

### 3.2 「タイムラインで調整」押下時の判定
- タイムラインを一度も生成/復元していない場合 → 原稿・英訳を新規パースして生成する。
- 既にタイムライン状態を持っている場合:
  - 現在の原稿テキスト**および**英訳テキストが、現在の `subs` から3.3節の書き戻しルールで再構成した文字列といずれも**完全一致**（コードポイント単位、正規化なし）→ 保存済みのタイムライン状態（`subs` / `edited` / cps / ズーム段 / ヘッド位置 / 履歴）をそのまま復元する。再パースは行わない。
  - どちらか一方でも一致しない（原稿または英訳が編集された）→ 確認ダイアログ「原稿または英訳が変更されています。タイムラインを再構築すると、手動調整した尺はリセットされます。よろしいですか？」を表示。OKなら原稿・英訳を新規パースして生成し直す（`edited` はすべて `false` に戻り、履歴・ヘッド位置は初期化。ズーム段・calibration・フォントサイズは維持）。キャンセルなら何もしない。

### 3.3 書き戻し（原稿に戻る）
- 「原稿に戻る」押下時、現在のクリップ列から原稿テキスト・英訳テキストをそれぞれ再構成し、両方のtextareaに反映する。**確認ダイアログは表示しない。**
- 原稿の再構成ルール: `clips.map(c => c.text + c.delim).join('\n')`（各クリップの本文内の改行はそのまま保持）。
- 英訳の再構成ルール: `clips.map(c => c.en).join('\n')`（1クリップ = 1行）。
- この書き戻しテキストを再度パースすると、通常は元と同じクリップ分割になる（ラウンドトリップ一致）。
- **既知の制約:** 「残す」系文字（`؟` `?` `!` `—`）で終わるクリップをMで結合した場合、その文字は結合後の本文中（末尾ではなく中間）に残る。書き戻し後にこのテキストを再パースすると、本文中に残ったその文字が区切りとして再度検出され、結合前と同様に分割される。この場合のみラウンドトリップは一致しない。ただし3.2節の判定は「現在のテキストと書き戻しテキストの文字列比較」であり再パース結果の比較ではないため、通常の再入場（原稿・英訳を編集していない場合）ではこの制約は問題にならない。

## 4. 英訳の併記

> 番号付きコピー・貼り付け（右パネルの「番号付きでコピー」「英訳を貼り付け」）の詳細仕様は `docs/srtgen-translation-roundtrip-spec.md` を参照。「適用」は押下時点のtextareaを常に再パースし、貼り付けに含まれる番号のクリップを無条件に上書きする（「空欄のみ埋める/すべて上書き」の2モードは廃止済み）。

### 4.1 データと入力
- 入力モードに英訳用テキストエリアを追加する。**1行 = 1クリップ**として、アラビア語のクリップ配列にインデックス順でマッピングする。
- 英訳側は**改行のみ**で分割する（区切り文字によるパースはしない）。各行は前後トリムする。空行もスキップせず1件として数える。ただし英訳欄が完全に空（未入力）の場合のみ0行として扱う。
- M（結合）: アラビア語と同様、`en` もスペース連結する。削除は連動して消える。S（時間トリム）は本文を分割しないため `en` に一切影響しない。

### 4.2 件数ズレの扱い
- アラビア語のクリップ数と英訳の行数を比較し、不一致なら件数のみの警告文を出す（内容の類似度等によるズレ位置推定は一切行わない）:
  - 不足時:「アラビア語 28件 / 英訳 25行 — 3行不足しています」
  - 超過時:「アラビア語 25件 / 英訳 28行 — 3行超過しています」
- **アラビア語側の分割は絶対に変更しない**。調整は英訳側だけで行う。
- 対応付け確認リスト（入力モードの右パネル、4.3節）の各行に、英訳のズレを直す操作を置く（英訳配列のみを操作する）:
  - 「ここから1つ下にずらす」= その位置に空行を挿入し、以降を1つ後ろへ。
  - 「ここを詰める」= その行を削除し、以降を1つ前へ。
- 行ごとに「対応する相手が存在しない」ことを機械的に判定して強調する（件数比較のみ。内容比較によるズレ発生箇所の推定は行わない）:
  - アラビア語はあるが英訳がない行 →「対応する英訳がありません」
  - 英訳はあるがアラビア語がない行 →「対応するアラビア語がありません」

### 4.3 右パネル（対応付け確認ビュー）
入力モードの右パネルは、時刻中心のライブプレビューから対応付け確認ビューに置き換える。
- 表示項目: #番号 / アラビア語本文（RTL）/ 英訳（LTR、空なら「(空)」表示）/ アラビア語の文字数。
- 時刻表示は持たない（タイムラインモードで確認するため）。
- 件数ズレ・行対応の警告は4.2節のとおり。

### 4.4 タイムライン表示
- 各クリップ内を2段にする。上段 = アラビア語（RTL）、下段 = 英訳（小さめ・二次テキスト色）。
- クリップ幅が狭い場合の省略表示は従来通り。英訳分だけクリップの高さを拡張する。

## 5. 9:16 実寸プレビュー

### 5.1 配置と基本仕様
- タイムラインモードのプレビューは 9:16 の枠（既定幅320px、`aspect-ratio: 9/16`）で表示する。
- **枠内はアラビア語のみ。英訳は枠の外（直下）に小さく添える。**
- 枠の背景は中間グレー（`#808080`）固定（ライト/ダークモードに関わらず変化しない）。実際の映像上での白抜き文字の視認性確認のため。
- 安全領域を1080×1920基準でガイド枠（破線）表示する: 左右各90px（実効幅900px = `SAFE_WIDTH_1080`）、上100px、下300px。プレビュー幅に比例してスケールする。
- 字幕のベースラインは映像下端から `SUBTITLE_BASELINE_FROM_BOTTOM = 390`（1080px基準、実機実測値）の位置に置く。実装上は字幕テキストのコンテナ要素の下端をこの位置に固定し（`position:absolute; bottom: 390×(プレビュー幅/1080)px`）、2行の場合は上方向に積む近似とする。

### 5.2 フォントとストローク
- フォントは `font-family: "Times New Roman", serif; font-weight: bold`（CapCutの「Times New Roman Negreta」= Times New Roman Boldに相当）。
- CapCutのフォントサイズ数値は1080×1920キャンバス上のemサイズとして扱う（既定 `FONT_SIZE_DEFAULT = 55`）。
- 実測・判定用フォントサイズ（1080px空間、プレビュー縮尺は掛けない）: `fontSize × calibration`。
- プレビュー表示用CSSフォントサイズ: `fontSize × calibration × (プレビュー幅 / 1080)`。
- 行間は `line-height: 1.3` を明示指定する。
- `calibration`（既定1.0、範囲0.80〜1.30、刻み0.01）とフォントサイズ（既定55、数値入力可）はUIから調整可能で、localStorageに永続化する。
- 縁取り: `color:#fff; -webkit-text-stroke: {S}px #000; paint-order: stroke fill;`。`paint-order` は必須（省略するとストロークが文字内側を侵食して細く見える）。ストローク幅 `STROKE_WIDTH_AT_1080 = 6`（1080px空間）をプレビュー幅に比例させる。

### 5.3 幅の測定
- Canvas 2D の `measureText` を使い、フォントは `bold {fontSize×calibration}px "Times New Roman"` を1080px空間の実寸で測る（プレビューの縮尺では測らない）。
- 改行を含む場合は行ごとに測り、最大値を採用する。
- 測定値には `STROKE_WIDTH_AT_1080` を加算する（判定に使う描画幅はアウトライン分を含む）。
- `document.fonts.ready` の解決後に再測定・再描画する。

## 6. 行数判定（3値）

各クリップについて、次の順で判定しバッジを表示する。

1. 本文全体が1行で安全幅（900px、`SAFE_WIDTH_1080`）以内 → **「1行」**
2. 1行では超えるが、単語境界（スペース）で分割した際に両側の描画幅の差が最小になる位置で2分割したときの最長行が安全幅以内 → **「2行推奨」**
3. 2行にしても最長行が安全幅を超える、または改行が既に2つ以上（3行以上）ある → **「溢れ」**

- 判定はあくまで表示上のヒントであり、**自動でテキストを改変してはならない**。
- バッジはタイムラインのプレビュー枠付近と、編集モーダル内の両方に表示する。実測値（描画幅／安全幅）も併記する。

## 7. 編集モーダル

- プレビュー枠のダブルクリックで、選択中クリップの編集モーダルを開く。編集モーダルが開いている間はタイムラインの全キーボードショートカットを無効化する。
- アラビア語本文は常時 `<textarea>`（改行入力可）。旧来の「改行なしはinput/改行ありはtextarea」という分岐は撤廃した。
- モーダル内に英訳の入力欄（LTR、`<input>`）を持つ。
- モーダル内に選択クリップの9:16縮小プレビューと行数判定バッジを表示し、アラビア語本文の入力に追随してリアルタイム更新する。
- 「自動で2行に分割」: 6節の判定と同じアルゴリズムで求めた単語境界位置に改行を1つ挿入する（既に改行がある場合は何もしない）。
- 「1行に戻す」: 本文中の改行をすべて半角スペース1つに置換する。
- **上記2つの操作、および保存操作は尺（`durMs`）を一切変更しない。** その旨をモーダル内に明記する。
- 「保存」でアラビア語本文・英訳をクリップに反映し（変更があれば `edited:true` にしてUndo履歴にpush）、モーダルを閉じる。「キャンセル」または背景クリック・Escで変更を破棄して閉じる。

## 8. 編集モードUI（コントロールバー・タイムライン本体）

### 8.1 ヘッダー（コントロールバー）
- 再生/停止ボタン（再生中はアイコン切替）/ 再生速度ボタン（`1x`表示、クリックで循環切替）
- ↑ボタン（前のクリップへ）/ ↓ボタン（次のクリップへ）
- 現在時刻 / 合計時間 の表示（`M:SS.d` 形式、常時更新）
- 「S ここで切る」「M 結合」「戻す（Undo）」ボタン
- cpsスライダー（8〜18、生成時の値を初期値）
- 「JSON保存」「JSON読み込み」ボタン（timeline.jsonの手動書き出し/読み込み。10.1節）
- 「原稿に戻る」「SRTダウンロード」ボタン
- 操作ヒントの1行テキスト（直近の操作結果メッセージ表示と兼用。ズーム段変更時にも一時的に表示）

### 8.2 タイムライン本体
- 横スクロール可能なコンテナ。
- **表示ズーム**: X（ズームイン）/ Z（ズームアウト）キーで、px/秒を段階的に変更する。段は `[20, 35, 50, 75, 100, 150, 200, 300, 400]`、初期値は75（従来の80px/secに最も近い段）。**ズームは見た目（px/sec）のみを変え、尺・時刻・SRT出力には一切影響しない。**
  - ズーム時は再生ヘッドの画面上のX座標を保つようスクロール位置を補正する。ヘッドが画面外にある場合はビューポート中央の時刻を基準にする。
- 秒目盛りルーラー。目盛り間隔はズーム段に応じて `[5, 2, 1, 0.5, 0.1]` 秒から、ラベル同士が40px以上離れる最小間隔を自動選択する。**ルーラークリックでその時刻に頭出し**。
- 字幕クリップ（4.4節の2段表示）。再生ヘッドが乗っているクリップは強調表示（枠色・背景色変更）。`edited:true` のクリップは左端に細いアクセントカラーのバーで視覚的に区別する。
- クリップ右端に**リサイズハンドル**（幅10px程度、`cursor: ew-resize`）。ドラッグで尺変更（px→msをその時点のズーム段から算出し1ms単位に丸め、最小300ms。スナップなし）。変更中もリアルタイムで後続がリップルして再描画される。
- **再生ヘッド**: 赤い縦線＋上部に小さなつまみ。再生中は実時間で右へ移動。ヘッドが画面端に近づいたら自動横スクロールで追従。

### 8.3 cpsスライダーと再計算
- cpsスライダーを変更すると、`edited:false` のクリップのみ、自身のテキストの文字数（アラビア語本文のみ・スペース込み・改行除く・コードポイント単位）から尺(ms)を再計算する。`edited:true` のクリップは一切変更しない。
- リップルにより開始時刻は自動で再配置される。
- 入力モードのcps数値入力とは同じ値を共有する（編集モードでの変更は入力モード側にも反映される）。

## 9. 操作仕様

| 操作 | 挙動 |
|---|---|
| スペース | 再生/停止のトグル。末尾到達で自動停止。停止状態で末尾にいる場合、再生開始で先頭から。 |
| ↑ / ↑ボタン | クリップ頭から150msより進んでいれば**現在クリップの頭**へ、頭付近なら**前のクリップの頭**へ（音楽プレイヤーの「戻る」挙動）。 |
| ↓ / ↓ボタン | 次のクリップの頭へ。最終クリップでは何もしない。 |
| S / 「S ここで切る」 | ヘッドが乗っているクリップの尺を `ヘッドms − クリップ開始ms` に変更。**テキスト・英訳は変更しない**（時間のみのトリム）。結果が300ms未満なら拒否してヒント表示。後続はリップル。 |
| M / 「M 結合」 | ヘッド位置のクリップと右隣を結合。テキスト・英訳とも半角スペース連結、尺は合算、`delim` は右クリップのものを引き継ぐ（左クリップの `delim` は破棄）。最終クリップでは拒否してヒント表示。 |
| Delete / Backspace | ヘッド位置のクリップを削除（英訳も連動して消える）。後続はリップルで詰まる。残存クリップの `edited` フラグには影響しない。 |
| クリップ右端ドラッグ | 尺変更（リップル、1ms単位）。 |
| クリップ本体クリック / ルーラークリック | その位置に頭出し。 |
| X / Z | ズームイン / ズームアウト（8.2節）。 |
| プレビュー枠ダブルクリック | 編集モーダルを開く（7節）。 |
| Ctrl+Z（macOSはCmd+Z） | Undo。 |

### Undo
- 対象: 尺変更（ドラッグは1ドラッグ=1履歴）、S、M、削除、テキスト・英訳編集（モーダル保存）、cps再計算（スライダー操作は1回の確定操作=1履歴）。すべて。
- 実装: 操作前に `subs` のディープコピー（`JSON.stringify` で可）をスタックにpush。上限50件。Redoは不要。
- Undo履歴は永続化（localStorage）の対象外。

### キーボードイベントの注意
- ショートカットは編集モーダルが開いている間は無効化すること。
- スペースのデフォルトスクロールは `preventDefault` すること。
- Ctrl/Cmd+Z（Undo）と単体のZ（ズームアウト）を区別すること。

## 10. 永続化（localStorage自動保存）

- 保存キー: `srtgen:session:v1`。保存単位は直近1セッションのみ（上書き保存）。
- スキーマバージョン: `version: 4`（動画トラック機能の撤去に伴い`master`/`segments`を廃止）。`version: 3`（動画トラック撤去前）のデータも字幕部分（`manuscript`/`translation`/`clips`等）のみ読み取り、`master`/`segments`は無視して移行する。
- 保存内容: 原稿テキスト・英訳テキスト・cps・BOM設定・現在のモード（`input`/`edit`）・clips（`text`, `durMs`, `delim`, `edited`, `en`）・ズーム段・ヘッド位置(ms)・calibration・フォントサイズ。Undo履歴は含まない。
- 読み込み時にバージョン不一致（v3以外の旧バージョン含む）・JSONパース失敗・想定外の構造（型不正・必須フィールド欠落等）を検出した場合は、例外を投げずに黙って破棄し初期状態から開始する。
- 保存タイミング: 状態変更時に300msデバウンス。ドラッグ中・cpsスライダーのドラッグ中・再生中のヘッド位置更新は保存対象外とし、確定時（pointerup / changeイベント / 再生停止時など）にのみ保存する。
- `localStorage.setItem` が失敗した場合（`QuotaExceededError` 等）は例外を握りつぶし、保存できなくてもアプリの動作は継続する。
- ページ読み込み時に自動復元する。復元した場合のみ、ヘッダ付近に控えめな表示（「前回の続きを復元しました」＋「新規作成」ボタン）を出す。
- 「新規作成」ボタン押下 → 確認ダイアログ → OKでlocalStorageをクリアしページを再読み込みして初期状態に戻す。

### 10.1 timeline.jsonファイル保存/読み込み

- localStorageの自動セッション保存とは別に、作業状態（`subs` / `cps` / スタイル）だけを手動でファイルに書き出し・読み込みできる。他端末への持ち出しやバックアップが主目的で、原稿テキスト・翻訳・モード・ズーム段・ヘッド位置は含まない。
- 「JSON保存」押下でファイル名 `timeline.json`（Blob + a[download]方式）としてダウンロードする。
- 「JSON読み込み」押下でファイル選択ダイアログを開き、選択したJSONを読み込む。読み込み成功時はUndo履歴をクリアし、タイムラインを再描画する。
- スキーマバージョン: `version: 2`。保存内容は `subs`（`text`, `durMs`, `edited`, `delim`, `en`）、`cps`、`style`（`fontSize`, `calibration`）のみ。
- 読み込み時にバージョン不一致（`version: 1`のみ後方互換で受け入れ。字幕部分は同一構造のため復元し、旧`master`/`segments`フィールドがあっても無視する）・JSONパース失敗・型不正・必須フィールド欠落を検出した場合は、例外を投げずに読み込みを拒否しヒントテキストで通知する。

## 11. 非スコープ（やらないこと）

- 動画ファイルの読み込み・プレビュー・動画トラックの編集（CapCut等の動画編集ソフト側の役割。将来の再導入候補ではあるが、データモデルが壊れない範囲で拡張点を意識するのみで実装しない）
- MP4への字幕焼き込み書き出し（CapCutのSRT読み込み機能を利用する前提。本ツールはSRT/timeline.jsonの生成のみを担う）
- 外部ライブラリの導入（React・ドラッグ系ライブラリ等一切不可。Vanilla JS + Pointer Events）
- Redo、複数選択、クリップの並べ替え（順序は原稿順で固定）
- fpsスナップ（CapCut実機で1フレームの隙間が出た場合に別途検討）
- 英訳のSRT出力、英訳の自動翻訳
- 英訳側の自動アライメント推定（ズレ修正は手動操作のみ。4.2節の強調表示は件数比較のみで内容は一切見ない）

## 12. テスト

`tests/logic.test.js` に実装（既存テストは全て維持・全PASSが条件）:

1. リップル・トリム・トリム下限・結合（テキスト/英訳のスペース連結、delim引き継ぎ）・削除・SRT出力・Undo（既存、ms/en対応済み）
2. **ms精度**: 多数クリップ（100枚超）の累積でも整数演算のみのため誤差ゼロであること
3. **ズーム無影響**: 全ズーム段で `subsToCues` / `buildSrt` の出力が完全に同一であること
4. **ラウンドトリップ**: アラビア語・英訳とも通常ケースで書き戻し→再パースが元と一致すること。既知の例外（残す文字終わりのクリップをM結合した場合）は再パース後にクリップ数が変わることを明示的に確認すること
5. **edited尺の維持**: 原稿・英訳とも未編集判定（textEquals）がtrueの場合、再パースを経ずにeditedクリップの手動調整尺が保持されること
6. **cps/SRTのen非依存**: cps算出(durMs)・SRT出力がenの内容・有無に一切影響されないこと
7. **SRTに英訳が含まれない**こと
8. **2行字幕のSRT複数行キュー出力**
9. **行数判定の3値分岐**: 境界値（安全幅ちょうど、安全幅+1px）を含む
10. **calibration連動**: calibration変更でプレビューのフォントサイズと判定用の実測フォントサイズが同じ比率で変化すること
11. **ベースライン・安全領域**: プレビュー幅に比例してスケールすること（実測はPlaywrightで別途確認）
12. **ストローク幅の加算**: 判定に使う描画幅にストローク幅が加算されていること
13. **英訳の対応付け**: `splitEnglishLines`（空行を1件として数える／完全な空文字列は0行）、`buildAlignmentWarning`、`rowMismatchMessage`（件数比較のみ）、`shiftEnglishDown`/`compactEnglish`（英訳のみ操作しアラビア語側は不変）
14. **永続化(v4)**: 有効なセッションのserialize/deserializeが往復できること。v3（`master`/`segments`付き）のデータは字幕部分のみ復元できること。バージョン不一致（v3以外の旧バージョン含む）・JSONパース失敗・型不正の場合にdeserializeがnullを返す（例外を投げない）こと

ロジック（clipAt、リップル計算、トリム、結合、削除、SRT生成、書き戻し、ズーム変換、行数判定、英訳対応付け、セッション検証）はUIから分離した純粋関数として実装し、Nodeでテスト可能にすること。行数判定・自動分割は `measureFn` を呼び出し側から注入する設計とし、実際のcanvas測定に依存せずNodeでテストできるようにする。
